== NetApp Disaster Recovery pour les datastores NFS

[role="lead"]
La mise en œuvre de la reprise après sinistre via la réplication au niveau des blocs du site de production vers le site de reprise après sinistre est une méthode résiliente et rentable pour protéger les charges de travail contre les pannes de site et les événements de corruption de données, tels que les attaques de ransomware.  À l’aide de la réplication NetApp SnapMirror , les charges de travail VMware exécutées sur des systèmes ONTAP locaux avec une banque de données NFS peuvent être répliquées vers un autre système de stockage ONTAP situé dans un centre de données de récupération désigné où VMware est également déployé.

Cette section du document décrit la configuration de NetApp Disaster Recovery pour configurer la reprise après sinistre des VM VMware sur site vers un autre site désigné. Cette configuration comprend l'agent Console, l'intégration des baies ONTAP, la définition des sites et l'association de VMware vCenter. En outre, ce document détaille la configuration de la réplication entre les sites, ainsi que la mise en place et le test d'un plan de reprise. La dernière section fournit des instructions pour effectuer un basculement complet du site et pour revenir en arrière lorsque le site principal est rétabli et remis en ligne.

En utilisant Disaster Recovery, qui fait partie de NetApp Data Services, les entreprises peuvent facilement découvrir leurs vCenters VMware sur site et leur stockage ONTAP. Les organisations peuvent ensuite créer des groupes de ressources, créer un plan de reprise après sinistre, l'associer à des groupes de ressources et tester ou exécuter le basculement et le rétablissement. SnapMirror fournit une réplication de blocs au niveau du stockage pour maintenir les deux sites à jour avec les modifications incrémentielles, ce qui permet d'obtenir un objectif de point de récupération (RPO) pouvant aller jusqu'à 5 minutes. De plus, il est possible de simuler des procédures de reprise après sinistre sans affecter la production ni entraîner de coûts de stockage supplémentaires.

Disaster Recovery exploite la technologie ONTAP FlexClone pour créer une copie à faible encombrement du datastore NFS à partir du dernier Snapshot répliqué sur le site de reprise après sinistre. Une fois le test de reprise après sinistre terminé, les clients peuvent facilement supprimer l'environnement de test sans affecter les ressources de production répliquées. En cas de basculement réel, Disaster Recovery orchestre toutes les étapes nécessaires pour mettre automatiquement en ligne les machines virtuelles protégées sur le site de reprise après sinistre désigné en quelques clics. Le service inverse également la relation SnapMirror vers le site principal et réplique toutes les modifications du site secondaire vers le site principal pour une opération de rétablissement, si nécessaire. Toutes ces fonctionnalités sont proposées à une fraction du coût des autres solutions bien connues.

[[getting-started]]
=== Commencer

Pour commencer avec NetApp Disaster Recovery, utilisez NetApp console, puis accédez au service.

. Connectez-vous à Console.
. Dans la navigation de gauche de Console, sélectionnez Protection > Reprise après sinistre.
. Le Disaster Recovery Dashboard s'affiche.
+
image:dr-draas-nfs-002.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]



Avant de configurer le plan de reprise après sinistre, assurez-vous que les conditions préalables suivantes sont remplies :

* L’agent Console est déployé.
* L'agent dispose d'une connectivité aux systèmes de stockage ainsi qu'aux vCenter source et de destination.
* Un cluster ONTAP avec une SVM sur laquelle le service NFS est activé est disponible.
* Les systèmes de stockage NetApp sur site hébergeant des banques de données NFS pour VMware sont ajoutés dans Console.
* La résolution DNS doit être en place lors de l'utilisation de noms DNS.  Sinon, utilisez les adresses IP pour le vCenter.
* La réplication SnapMirror est configurée pour les volumes de banque de données NFS désignés.
* Assurez-vous que l’environnement dispose de versions prises en charge des serveurs vCenter Server et ESXi.


Une fois la connectivité établie entre les sites source et de destination, procédez aux étapes de configuration, qui devraient prendre quelques clics et environ 3 à 5 minutes.


NOTE: NetApp recommande de déployer le Console agent sur le site de destination ou sur un site tiers, afin que le Console agent puisse communiquer via le réseau avec les ressources source et de destination.

[[configuring-storage-replication-between-source-site-array-and-destination-site-array]]
=== Configuration de la réplication de stockage entre la matrice de sites source et la matrice de sites de destination

SnapMirror assure la réplication des données dans un environnement NetApp. Basée sur la technologie Snapshot de NetApp, la réplication SnapMirror est extrêmement efficace, car elle ne réplique que les blocs qui ont été modifiés ou ajoutés depuis la mise à jour précédente. SnapMirror se configure facilement à l'aide de NetApp OnCommand System Manager ou de l'interface de ligne de commande ONTAP. NetApp Data Services crée également la relation SnapMirror, à condition que le peering du cluster et du SVM soit configuré au préalable.

Dans les cas où le stockage principal n'est pas complètement perdu, SnapMirror offre un moyen efficace de resynchroniser les sites principal et de reprise après sinistre. SnapMirror peut resynchroniser les deux sites en retransférant uniquement les données modifiées ou nouvelles du site de reprise après sinistre vers le site principal, simplement en inversant les relations SnapMirror. Cela signifie que les plans de réplication dans Disaster Recovery peuvent être resynchronisés dans les deux sens après un basculement, sans recopier l'intégralité du volume. Si une relation est resynchronisée dans le sens inverse, seules les nouvelles données écrites depuis la dernière synchronisation réussie de la copie Snapshot sont renvoyées vers la destination.


NOTE: Si une relation SnapMirror est déjà configurée pour le volume via l’interface de ligne de commande ou System Manager, NetApp Data Services reprend cette relation et poursuit le reste des opérations du flux de travail.



[[how-to-set-it-up-for-vmware-disaster-recovery]]
=== Comment le configurer pour la récupération après sinistre VMware

Le processus de création de la réplication SnapMirror reste le même pour toute application donnée. Le processus peut être manuel ou automatisé. La méthode la plus simple consiste à utiliser NetApp Console pour configurer la réplication SnapMirror en faisant simplement glisser-déposer le système ONTAP source de l'environnement vers la destination afin de lancer l'assistant qui vous guidera tout au long du reste du processus.

La reprise après sinistre peut également automatiser ce processus à condition que les deux critères suivants soient remplis :

* Les clusters source et de destination ont une relation d’homologue.
* La SVM source et la SVM de destination ont une relation homologue.

[[what-can-disaster-recovery-do-for-you]]
=== Que peut faire Disaster Recovery pour vous?

Une fois les sites source et de destination ajoutés, Disaster Recovery effectue une analyse approfondie automatique et affiche les machines virtuelles ainsi que leurs métadonnées associées. Disaster Recovery détecte et renseigne également automatiquement les réseaux et les groupes de ports utilisés par les machines virtuelles.

image:dr-draas-nfs-009.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Une fois les sites ajoutés, les machines virtuelles peuvent être regroupées en groupes de ressources. Les groupes de ressources de reprise après sinistre vous permettent de regrouper un ensemble de machines virtuelles dépendantes en groupes logiques qui incluent leur ordre de démarrage et leurs délais de démarrage à appliquer lors de la reprise. Pour commencer à créer des groupes de ressources, accédez à *Groupes de ressources* et cliquez sur *Créer un groupe de ressources*.

image:dr-draas-nfs-010.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

image:dr-draas-nfs-011.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]


NOTE: Le groupe de ressources peut également être créé lors de la création d’un plan de réplication.

L'ordre de démarrage des machines virtuelles peut être défini ou modifié lors de la création de groupes de ressources en utilisant un simple mécanisme de glisser-déposer.

image:dr-draas-nfs-012.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Une fois les groupes de ressources créés, l’étape suivante consiste à créer le plan d’exécution ou un plan de récupération des machines virtuelles et des applications en cas de sinistre.  Comme mentionné dans les conditions préalables, la réplication SnapMirror peut être configurée au préalable ou DRaaS peut la configurer à l'aide du RPO et du nombre de rétention spécifiés lors de la création du plan de réplication.

Tout d’abord, sélectionnez le vCenter source, puis sélectionnez le vCenter de destination.

[[test-failover]]
=== Test de basculement

Le test de basculement dans Disaster Recovery est une procédure opérationnelle qui permet aux administrateurs VMware de valider entièrement leurs plans de reprise sans perturber leurs environnements de production. Lors d’un test de basculement, Disaster Recovery crée des copies NetApp FlexClone à faible encombrement des volumes de datastore NFS répliqués sur le système de stockage DR. Ces volumes FlexClone sont ensuite montés sur les hôtes ESXi du site DR, et les VM sont mises sous tension dans un réseau de test isolé. Ce processus permet aux administrateurs de vérifier que leurs plans de reprise après sinistre fonctionneront comme prévu en cas de sinistre réel.

image:dr-draas-nfs-024.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

La reprise après sinistre intègre la possibilité de sélectionner l’instantané comme fonctionnalité facultative lors de l’opération de test de basculement. Cette fonctionnalité permet à l’administrateur VMware de vérifier que toutes les modifications récemment apportées à l’environnement sont répliquées vers le site de destination et sont donc présentes pendant le test. Ces modifications incluent les correctifs du système d’exploitation invité de la machine virtuelle

image:dr-draas-nfs-025.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Lorsqu'un administrateur VMware exécute une opération de basculement de test, Disaster Recovery automatise les tâches suivantes :

* Déclenchement des relations SnapMirror pour mettre à jour le stockage sur le site de destination avec toutes les modifications récentes apportées sur le site de production.
* Création de volumes NetApp FlexClone des volumes FlexVol sur la baie de stockage DR.
* Connexion des banques de données NFS dans les volumes FlexClone aux hôtes ESXi sur le site DR.
* Connexion des adaptateurs réseau VM au réseau de test spécifié lors du mappage.
* Reconfiguration des paramètres réseau du système d’exploitation invité de la machine virtuelle tels que définis pour le réseau sur le site DR.
* Exécution de toutes les commandes personnalisées qui ont été stockées dans le plan de réplication.
* Mise sous tension des machines virtuelles dans l’ordre défini dans le plan de réplication.
+
image:dr-draas-nfs-026.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]





[[cleanup-failover-test-operation]]
=== Opération de test de basculement de nettoyage

L'opération de test de basculement de nettoyage se produit une fois le test du plan de réplication terminé et l'administrateur VMware répond à l'invite de nettoyage.

image:dr-draas-nfs-027.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Cette action réinitialisera les machines virtuelles (VM) et l’état du plan de réplication à l’état prêt.

Lorsqu'un administrateur VMware effectue une opération de récupération, Disaster Recovery suit le processus suivant :

. Il met hors tension chaque machine virtuelle récupérée dans la copie FlexClone qui a été utilisée pour les tests.
. Il supprime le volume FlexClone qui a été utilisé pour présenter les machines virtuelles récupérées pendant le test.




[[planned-migration-and-fail-over]]
=== Migration planifiée et basculement

Disaster Recovery propose deux méthodes pour effectuer un basculement réel : la migration planifiée et le basculement. La première méthode, la migration planifiée, intègre l’arrêt des VM et la synchronisation de la réplication du stockage dans le processus afin de récupérer ou de déplacer effectivement les VM vers le site de destination. La migration planifiée nécessite un accès au site source. La seconde méthode, le basculement, est un basculement planifié ou non planifié dans lequel les VM sont récupérées sur le site de destination à partir du dernier intervalle de réplication du stockage qui a pu s’achever. Selon le RPO défini dans la solution, une certaine perte de données est à prévoir dans le scénario de DR.

image:dr-draas-nfs-028.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Lorsqu'un administrateur VMware effectue une opération de basculement, Disaster Recovery automatise les tâches suivantes :

* Interrompez et basculez les relations NetApp SnapMirror .
* Connectez les banques de données NFS répliquées aux hôtes ESXi sur le site DR.
* Connectez les adaptateurs réseau VM au réseau du site de destination approprié.
* Reconfigurez les paramètres réseau du système d’exploitation invité de la machine virtuelle tels que définis pour le réseau sur le site de destination.
* Exécutez toutes les commandes personnalisées (le cas échéant) qui ont été stockées dans le plan de réplication.
* Mettez sous tension les machines virtuelles dans l’ordre défini dans le plan de réplication.

[[failback]]
=== Retour arrière

Une restauration est une procédure facultative qui restaure la configuration d’origine des sites source et de destination après une récupération.

image:dr-draas-nfs-030.png["Figure montrant une boîte de dialogue d'entrée/sortie ou représentant un contenu écrit"]

Les administrateurs VMware peuvent configurer et exécuter une procédure de restauration automatique lorsqu’ils sont prêts à restaurer les services sur le site source d’origine.

*REMARQUE :* Disaster Recovery réplique (resynchronise) toutes les modifications vers la machine virtuelle source d’origine avant d’inverser le sens de la réplication. Ce processus démarre à partir d’une relation ayant terminé le basculement vers une cible et comprend les étapes suivantes :

* Mettez hors tension et désenregistrez les machines virtuelles et les volumes sur le site de destination sont démontés.
* Rompre la relation SnapMirror sur la source d'origine est rompue pour la rendre en lecture/écriture.
* Resynchronisez la relation SnapMirror pour inverser la réplication.
* Montez le volume sur la source, mettez sous tension et enregistrez les machines virtuelles sources.


Pour plus de détails sur l'accès à Disaster Recovery et sa configuration, consultez le link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["Découvrez NetApp Disaster Recovery pour VMware"].
